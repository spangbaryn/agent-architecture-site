The four operations: write, select, compress, isolate

Name any context failure by the move the harness failed to make, and name the fix by the move it should make on purpose.

Freshness-checked 2026-09-05 · builds on 0.1, 0.3, 0.4, 1.1 · ~13 min read

1Why this exists

1.1 handed you a diagnosis and no treatment. You now know that every token in the window spends from a finite attention budget, so the question is never "does it fit" but "does this token pay for its seat." Fine. A token has stopped paying for its seat. What, exactly, can you do about it?

The answer turned out to be short, and it took the field until mid-2025 to say it out loud. By then every team shipping a long-running agent had independently invented the same handful of tricks under different names: scratchpads, todo files, RAG, tool loadouts, summarizers, "just spawn a fresh agent for that part." Manus had one vocabulary, Cognition another, Anthropic a third. LangChain's July 2025 post collapsed the pile into four verbs (write, select, compress, isolate), and Drew Breunig's June 2025 pair of posts gave the other half: the four ways a window goes bad (poisoning, distraction, confusion, clash). Within a year every vendor write-up cited both lists by name, which is what a vocabulary winning looks like.

The pressure that forced this was time. A single call has one window and no history; an agent that runs for hours rewrites its window on every turn, and the harness is the only thing standing between "append everything" and "the model repeats itself at 100k tokens." 0.4 showed you the zero-operation baseline: AutoGPT's "append-everything context with the vector-store bolt-on" was an agent whose harness could not do anything to the window except grow it. 0.1 told you that "the harness is what you get to design." This topic is the list of what the harness can actually do.

2The mental model

Carry this out of the room Between two model calls the harness has exactly four moves on the window: move something out, bring something in, shrink what stays, or wall something off. Every context failure is one of those moves made too late, and every fix is one made on purpose.

The four moves are the four operations, restated as what physically happens to the window:

OperationThe moveWhat it looks like in a shipped agent
WriteMove something out of the window into durable state the model can get backScratchpads, todo.md, memory files, Anthropic's memory tool, Deep Agents offloading a tool result to a file and leaving a path behind
SelectBring something into the window, now, because this step needs itRetrieval of any kind, tool loadout (only the tools this task needs), skills loaded by name, reading a file the agent wrote earlier
CompressShrink what stays: same window, fewer tokensCompaction summaries, tool-result clearing, thinking-block clearing, truncating old tool arguments
IsolateWall something off so it never enters this window at allSubagents with fresh contexts, sandboxes that return a string instead of a transcript, separate memory namespaces per concern

Notice what the four have in common: each is a decision about a token's relationship to the window (out, in, smaller, never). That is why the list is complete. There is no fifth thing a harness can do to a token between calls; the frontier work you will see below does not add a fifth verb, it makes the existing ones reversible.

The failure modes are the same four moves seen from the other side. Breunig's list, and the move that was missing:

FailureWhat you observeMissing move
PoisoningAn error (a hallucinated fact, a bad tool result) enters and gets referenced on every later turn; the agent builds a plan around a goal that cannot be metIsolate (quarantine the untrusted step) and, once it is in, compress with intent (prune the bad entry, do not summarize it into permanence)
DistractionThe window is so long the model leans on its own history and repeats past actions instead of planning; Google's Pokémon-playing Gemini agent did this past 100k tokensWrite (offload) and compress, and earlier than you think
ConfusionSuperfluous material gets used anyway: the wrong tool out of eighty, an irrelevant document quoted with confidenceSelect (tool loadout, retrieval that returns less)
ClashTwo things in the window disagree (turn-2 instruction vs turn-9 document, an old note vs a new tool result) and the model picks one for no defensible reasonIsolate (keep the contradicting sources in separate windows and reconcile above them) and write that overwrites instead of appending

Quotable version for the newsletter: poisoning and distraction are problems of what stays, confusion is a problem of what enters, and clash is a problem of what coexists. The four operations are the four answers, one per axis, with compress covering "stays" from the other direction.

3The landscape

A landscape of: who decides when to make one of the four moves, and whether the move can be undone.
What varies: the trigger (nobody, a harness threshold, the model's own judgment) and the reversibility of what happens when it fires (destroyed vs recoverable). Four answers, from no trigger to a trigger that stops mattering.
Reading the diagrams: gray is shared structure; teal is what makes this approach different from the one above it; the amber dot marks where it breaks. The window box is the context window at the moment of the next model call. The dashed harness box is deterministic code, no model inside.

Append-only transcript Legacy

No operations at all. Every user turn, every tool result, every thought is appended, and the whole transcript is re-sent on every call until the window overflows. This is the 2023 chat-app default and the 0.4 AutoGPT shape, and it is still what you get from any framework the day before you configure it. Champions: nobody on purpose; it is where every agent starts.

Wins: nothing is ever lost, nothing needs designing, and the prefix is perfectly cacheable because it never changes (1.7). Costs: distraction arrives long before overflow; cost and latency climb every turn; there is no place for a fact to live except "somewhere in the middle."

Done right: a ten-turn support conversation or a single agentic step that reliably ends inside the window's reliable zone from 1.1. If the task cannot outgrow the window, operations are pure overhead, and the honest design is to not build them.

Harness-triggered operations Current

Deterministic code watches the window and fires a move at a threshold. Anthropic's server-side context editing clears old tool results once N have accumulated, and server-side compaction summarizes the transcript when input crosses a trigger (150,000 tokens by default). LangChain's Deep Agents offloads any tool result over 20,000 tokens to a file and leaves a path plus a ten-line preview in its place, and only summarizes when nothing is left to offload. No model judgment is involved in when; a model may be involved in how (the summary is written by one). Champions: Anthropic's platform, LangChain Deep Agents, every production harness by mid-2026.

Wins: predictable, testable, and cache-aware (the harness knows exactly when it invalidates a prefix, so it can clear enough at once to be worth it); Anthropic measured a 29% improvement on its agentic-search eval from context editing alone. Costs: a threshold is blind to what mattered; the tool result it clears at N+1 may be the one the next step needed, and a summary written at 150k tokens summarizes whatever happened to be there.

Done right: a coding agent whose bloat is predictable at build time: big file reads and long tool-call histories. Offload reads over a size, clear old tool results, compact late. The shape of the garbage is known, so a threshold is the right tool.

Model-driven operations through tools Current

The model makes the move itself, by calling a tool: writes a note, updates a todo.md, saves to a memory directory, calls compact_conversation, or delegates a subtask to a subagent (isolate as a tool call). Manus's file-as-context and recitation patterns, Anthropic's memory tool, Claude Code's memory directory and subagents, Deep Agents' write_todos and task tools are all this card. The harness supplies the tools; the model supplies the judgment. Anthropic's number for the pairing: 39% on the same eval when the memory tool joins context editing, versus 29% for editing alone. That 10-point gap is what model judgment about which tokens to keep is worth over a threshold that keeps the most recent ones.

Wins: the move is made by the only party that knows what the next step needs; the notes are inspectable and become memory for free (2.2); the pattern rides the model, so it gets better with each release rather than staler. Costs: the model has to remember to do it, and under pressure it forgets; every write costs a turn; quality is exactly the quality of what it wrote down (0.3's "a tool is a prompt" applies to the tool it uses on itself).

Done right: a research or planning agent whose important state is semantic, not size-shaped: "we ruled out approach B because of X." No threshold can find that sentence. A model writing it to a plan file, and re-reading the plan at the top of each step, can.

Reversible context: the log is the truth, the window is a view Emerging

Stop destroying anything. Every event goes to an append-only log outside the window; the window at each call is a selection from that log, transformed by the harness on the way in. Anthropic's Managed Agents (Apr 2026) is the cleanest statement: "the session is not Claude's context window," and the brain interrogates the session through getEvents() slices, rewinding a few events before a moment or rereading what led up to an action. Deep Agents moved the same direction in June 2026: evicted messages are appended to a conversation_history file before the summary replaces them, and the summary embeds the path so the agent can reopen it. Recursive Language Models (1.1's emerging card) are the research version: the prompt is a variable and the model slices it with code.

Wins: compress becomes a view choice instead of a guillotine; a wrong drop is a re-read, not a lost fact; the harness can change its context policy between runs (or model generations) without touching the record. Costs: someone still has to decide what to reread and when, so it inherits the trigger problem of the two cards above; storage and a real session service; re-reading is a cache miss and a latency hit; as of Sep 2026 it is a hosted product surface and a research pattern, not what most teams run.

Done right: a multi-hour agent doing audited work, where "why did it do that at step 340" has to be answerable and a lost tool result at step 12 cannot be allowed to silently change step 400. The record must outlive the window, so the record is the design.

Two things the cards cannot show. First, the two CURRENT cards are not rivals; Anthropic's own docs say to run both: compaction keeps the window small without client-side bookkeeping, and memory preserves what must survive it. The tree below decides which is primary. Second, the field's ordering of the four moves has quietly settled, and it is the reverse of what most teams build first: write before compress (offload, then summarize what is left), select before compress (fix retrieval before shrinking its noise), and compress last, because it is the only move that destroys information. Deep Agents encodes that ordering as literal control flow. The emerging card is what happens when you push it to the limit: never compress at all, only view.

4Choosing

When designing an agent, ask yourself these questions to decide how the four operations get triggered, and by whom:

Question 2 is load-bearing because it is the one whose answer changed this year. Until Managed Agents and the Deep Agents eviction file, "recoverable" was not on the menu; you picked a threshold or you trusted the model, and either way the dropped tokens were gone. Now the honest first question is whether you can afford to lose anything at all. Most tasks can, and the two CURRENT cards remain the right default for them. Question 3 then splits by whether the garbage has a predictable shape: size-shaped bloat wants a threshold; meaning-shaped bloat wants the model. Question 4's "not yet" leaf is worth taking seriously: an agent with no durable store has exactly one move available, shrink, and shrink is the lossy one.

5Seen in the wild

Anthropic's Managed Agents, the hosted long-horizon agent service written up in April 2026, is a useful specimen because it was designed around the four operations rather than adding them afterward. Its authors split an agent into three interfaces: a session (append-only log of everything that happened), a harness (the loop that calls Claude and routes tool calls), and a sandbox (where code runs). Each of the four operations lands on a different seam.

Write is total and automatic: the harness emits every event to the session as it happens, so nothing has to be "remembered" by a model. Select is positional: the brain asks for slices of the event stream, and can rewind a few events before a decision to see the lead-up. Compress is where the design gets pointed: the transformations that turn a slice into a window (organizing for cache hits, trimming, summarizing) live in the harness, deliberately separated from the durable session, because the authors say they cannot predict what context engineering future models will need. Isolate is the sandbox: the harness calls it exactly like any tool, execute(name, input) returning a string, so the container's transcript, file churn, and failures never enter the brain's window unless the brain asks. If the container dies, the model sees a tool error and decides whether to retry; if the harness dies, a new one wakes with the session ID and reads the log.

Two details reward a second look. The post opens by admitting an earlier harness added "context resets" because Sonnet 4.5 wrapped up tasks early when it sensed the limit approaching, and that on Opus 4.5 the resets had become dead weight. You already know this pattern from 0.4: "scaffolding that substitutes for model capability gets eaten by the next model release, while scaffolding that contains consequences survives every one of them." A reset that manages a model's anxiety is substitution; a durable log that survives crashes is containment. Managed Agents is the same team drawing the same line and moving the substitution-shaped context tricks out of the fixed interfaces into the swappable harness. The second detail is the security seam: credentials never reach the sandbox where generated code runs, so a prompt injection has nothing to steal from the environment it can touch. That is isolate doing safety work, which 7.2 will name as a whole stack.

One aside, and then we leave it alone: Claude Code is card three almost entirely, with a card-two compaction backstop. Its memory directory, todo list, and subagents are the model making its own moves; auto-compaction is the harness catching whatever the model did not.

The misconception "Context management means summarizing when you run out of room." It is the first thing every team builds and the last move the field now recommends. Compress is the only one of the four operations that destroys information, and a summary written at the limit is the mental model's definition of a move made too late: it compresses whatever happened to be in the window, at the moment attention was already thinnest. The production ordering that emerged in 2026 is write first (offload the big tool result and leave a path), select second (fix what enters before shrinking it), compress last and small (clear old tool results before you summarize anything), and, where you can afford it, never compress at all, just view. If the only operation your harness has is a summarizer, you have built the guillotine and skipped the three moves that keep it from being needed.

6Check yourself

A support agent, thirty turns in, asks the customer for the order number it was given on turn three. Your engineer proposes "summarize the conversation every ten turns." Which failure mode, which missing move, and why is the proposal the wrong move?

Distraction, with a "lost in the middle" flavor: the fact is in the window but the model is not attending to it. The missing move is write: the harness (or the model, through a tool) should have moved the order number out of the transcript into a small structured state block that sits near the top of every call, then select it back in as a labeled fact. Summarizing every ten turns is compress, which is lossy and may well drop the order number itself; it treats a placement problem as a size problem. Note that this is also the first appearance of 1.5's recitation pattern: a fact that keeps being needed gets re-written near the point of use.

You wired six MCP servers into a coding agent (eighty-odd tools). It has started calling search_issues when it meant search_code, and occasionally invents a parameter. Which failure mode, which missing move, and what does 0.3 add?

Confusion: superfluous tool definitions are being used because they are there. The missing move is select, specifically tool loadout: choose the subset of tools this task needs, per run or per step, rather than preloading all of them. 0.3 already told you why the descriptions are the culprit: "a tool is two things at once: a contract with a deterministic system, and a prompt aimed at a non-deterministic one," and eighty overlapping prompts is eighty chances to pick the wrong one. Breunig cites research that some models degrade past roughly twenty tools. If the loadout itself needs judgment, that is 1.6's progressive disclosure: load names and one-liners always, full definitions on demand.

A research agent quotes a revenue figure from a search snippet that was itself wrong. Every later draft cites it, and the final report builds a recommendation on it. Which failure mode, which missing move, and what would the emerging card have given you?

Poisoning: an error entered and was referenced on every subsequent turn. The primary missing move is isolate: the read step (search, extract, verify) should have run in its own context and returned only findings that passed a check, so an unverified snippet never entered the writer's window in the first place. This is 0.2's "verification as the ceiling on delegation" applied to context: the untrusted read gets a wall, the verified result gets a seat. Once poison is in, compress with intent is the repair, pruning the bad entry rather than summarizing it into permanence. The emerging card would have added a third option: rewind the session to the event before the bad figure entered and re-run from there, because nothing was destroyed. That is exactly the "wrong drop must be recoverable" case from the decision tree.

Done when Module 1's bar is "given any agent misbehavior, your first three hypotheses are all context hypotheses, and they are usually right." 1.1 gave you the first hypothesis (a token that is not paying for its seat). 1.2 gives you the vocabulary to make the other two: you can name which of the four failure modes you are looking at, name the move that was missing, and say who should have made it (harness threshold, model judgment, or a reversible log) and in what order (write and select before compress). 1.3 through 1.7 supply the mechanisms one move at a time: 1.3 is compress, 1.4 and 1.6 are select, 1.5 is write, and 1.7 is the bill for all of them.
