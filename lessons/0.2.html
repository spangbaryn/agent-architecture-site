The workflow-vs-agent spectrum

Place any system on the autonomy dial and say what each notch to the right costs.

Freshness-checked 2026-08-21 · landscape rebuilt 2026-08-22 with per-card diagrams · builds on 0.1 · ~12 min read

1Why this exists

Teams shipped "agents" in 2025 that were, on inspection, three prompts in a trench coat, and other teams shipped open loops that burned budget on tasks a router would have handled. Both groups argued about whether their thing was really an agent. The argument was the problem. Anthropic's Building Effective Agents replaced it with a spectrum: predefined code paths on one end, model-directed loops on the other. The question underneath is how much control flow you write and how much you hand to the model.

2The mental model

Carry this out of the roomThe question is never "is this an agent." It is "how much control flow did I delegate to the model, and can I verify what it does with it?"

Two consequences. Autonomy is not a property of the model, it is a property of your deployment; the same model is a workflow step in one system and an autonomous agent in another. And verification is the ceiling: you can safely delegate exactly as much control flow as you can mechanically check. Coding agents run hot because tests are ground truth. Research agents run cooler because "is this analysis good" has no cheap oracle.

The correction the field made in 2026 was not a retreat from agents. It was recognizing that autonomy is a dial, that most production value sits well below maximum, and that turning it up has a price you can state in advance. Carnegie Mellon and Salesforce measured roughly seventy percent failure on realistic office tasks; Gartner projects over forty percent of agentic projects cancelled by 2027. Those were failures of predictability, not intelligence.

Read the five cards below left to right as the dial turning up. Watch what happens to the loop arrow: absent, then owned by you, then shared, then fenced, then the model's alone.

3The landscape

A landscape of: how much control flow is handed to the model, and how is it fenced?
What varies: the position of the autonomy dial, from no loop at all to a loop the model owns end to end. Five notches, read left to right as the dial turns up; each notch trades predictability for adaptability.
Reading the diagrams: gray is structure every approach shares; teal is the element that makes this approach different from the one above it; the amber dot marks where it breaks.

The augmented single call Current

One model call with retrieval, tools, and a tight output contract. No loop at all. Anthropic's own guidance says to reach for this first and stop here if it passes your evals.

Wins: one unit of latency, one unit of cost, trivially testable, and it fails in ways you can read. Costs: cannot recover from its own mistakes, and cannot handle tasks whose shape you do not know in advance. Reach for it when: more often than you want to. A large share of shipped "agents" are this with extra steps.

Done right: Support-ticket triage: retrieve the tag taxonomy and three similar tickets, one call, JSON out with category and priority. It passes the eval set, so it ships as a single call and stays one.

Fixed workflows: chaining, routing, parallelization Current

You write the graph, the model fills the nodes. Chaining is a line, routing is a fork, parallelization is a fan-out.

Wins: priceable, cacheable, testable per node. Costs: novel inputs fall off the graph. Routing is underused; a cheap classifier in front of three specialized paths beats one prompt covering all three.

Done right: A weekly pipeline-recap email: pull CRM data, summarize per rep in parallel, merge, format to the template. The graph is identical every Monday, so every node is priced, cached, and tested on its own.

Evaluator-optimizer Current

Generate, evaluate, revise. The model owns the iteration count; you own the exit condition.

Wins: the cheapest reliability you can buy, when the evaluation is grounded. Costs: ungrounded self-critique converges on confident garbage.

Done right: Generating a SQL query where the evaluator actually runs it against a sample database and compares row counts to the expected answer. The referee is grounded, so each revision moves toward something real. Marketing copy graded by "does this sound good" is the same loop with no referee.

The bounded agent step Ascendant

A workflow shell with one genuinely agentic node inside fences: max iterations, cost cap, tool allowlist, a human gate on the irreversible. The shape of most production systems that work.

Wins: adaptive where the task needs judgment, deterministic everywhere else, blast radius bounded by construction. Costs: someone has to set the fences per step, and the defaults are never right.

Done right: The refunds path of a support agent: a router decides it is a refund case, then the model works freely among lookup and policy tools, capped at eight turns, with a human gate on any refund above a threshold. Judgment where the case is messy; a hard fence where the money moves.

The open agent loop Contested

The model owns control flow end to end. Decides what to do, how many times, when to stop.

Wins: the only thing that handles tasks whose shape depends on what gets discovered. Costs: unpredictable spend, early errors poison the trajectory, near-zero auditability. Reach for it when: you cannot hardcode the path but can still verify the result.

Done right: "Make the failing CI green" on an unfamiliar repo. Nobody can write the steps in advance, but CI is a binary verifier, so the loop can run open and the result still gets checked. Both halves of the test hold.

When designing an agent, ask yourself these questions to decide how far to turn the autonomy dial for a given step:

Ask this per step, not per product. The left branch is the agent side of the dial and its gate is verification: an open loop is only safe when a mechanical check exists, and an evaluator-optimizer only works when the evaluator is grounded in something other than the text. The right branch is the workflow side; the only reason to let a node improvise is judgment that changes with the input, and when it does, fence it.

5Seen in the wild

Deep research products occupy several positions at once. The outer shape is a workflow: decompose, search, synthesize, cite, write. Nobody lets the model decide whether to include citations. Inside the search step autonomy goes up sharply, because each subagent picks its own queries and the work is read-only, so the worst outcome is a wasted subagent rather than a deleted database. In the grammar above, that is a fixed chain whose "search" node is a bounded agent step.

The transferable habit: set the dial per step, not per product. Grant autonomy where actions are reversible and parallelism is real, withhold it where the output contract matters.

The misconceptionThat the spectrum is a maturity ladder with agents as the advanced version. It is a trade, not a ladder. Every step right sells predictability to buy adaptability, and if the task did not need adaptability you paid for nothing. The mature move is usually leftward: find the one step that genuinely needs judgment, make that agentic, hardcode the rest.

6Check yourself

Support product routes tickets to four paths; inside the refunds path the model picks among six tools freely. Where is this, and what must you check?

Routing outside, bounded agent step inside, which is a good shape. Check whether any of the six tools moves money irreversibly. If so it needs a human gate or a reversible staging step. The check is about blast radius, not the model's competence.

Your evaluator-optimizer loop produces worse output the longer it runs. Why?

The evaluator is not grounded, so it rewards qualities visible in the text rather than qualities the task requires, and each round amplifies the last. Fix the oracle before the prompt. If no oracle exists, delete the loop and take the single call.

A colleague says go fully autonomous because scaffolding will be obsolete in six months. Where does that break?

The strong version is often right: structure that compensates for a weak model becomes a cage for a strong one. But not all structure is compensation. Approval gates and cost caps exist because some actions are irreversible, not because the model is dumb. Model improvements dissolve scaffolding that substitutes for judgment, not scaffolding that contains consequences.
